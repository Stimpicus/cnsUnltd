# RESOURCE MODEL

The honest answer to "how do we budget this org," reached by the cost-benefit the
founder invited (decision D-012).

## Dollar budgets: NO
- The CEO function **cannot itemize credits per request** — no access to the meter.
- More fundamentally, operating cost is a **flat-rate plan**, not a per-use dollar
  meter. There are no dollars to allocate across divisions.
- A dollar-denominated budget process would be pure overhead with zero decision
  value. The cost-benefit comes out clearly against it.
- **Therefore: all operating-cost budget line items = ZERO.** Not as a fallback —
  as the correct answer.

## What we DO track

### 1. Service / supply costs — ACTUAL dollars, always
Real money spent on real things: hardware (e.g. the Elpis Orrery parts), domain
registration, any paid API or service, physical supplies. Recorded as actual,
per item, in this file's ledger section. This is the only real-money line.

### 2. CC throughput — the real scarce resource (not dollars)
The plan has a **usage envelope.** Many sessions running indefinitely can be
throttled. The genuine constraint is *how many divisions run hot at once* without
hitting the ceiling mid-cycle. **Infrastructure/Platform owns watching this** (its
"credit-budget monitoring" = usage-envelope monitoring, not dollar accounting). The
EA sequences division cadences so the swarm stays inside the envelope.

### 3. Founder decision-bandwidth — the scarcest resource of all
The single most limited input to the org is the founder's attention. The whole
merge-autonomy lesson generalizes: **127 branches → 6 decisions.** The EA's
standing objective is to keep the founder's decision queue *that* short — surface
only what genuinely needs the architect, batch it, present it decision-ready.
